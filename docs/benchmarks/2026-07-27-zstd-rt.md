# zstd-19 .rt compression benchmark — 2026-07-27

- **Machine:** Apple M3 Max, macOS, Metal build (`make macos`)
- **zstd library:** `zstd --version` → `*** Zstandard CLI (64-bit) v1.5.7, by Yann Collet ***`
- **Table:** `tables/ntlm_ascii-32-95#8-8_0_422000x1000000_0.rt`, 16,000,000 bytes (already sorted; verified with `crackalack_sort`)
- **Date:** 2026-07-27

> The benchmark table is 16 MB and fits entirely in page cache, so the raw `.rt`
> baseline is close to a memcpy and the compressed formats look worse on
> end-to-end lookup time than they would at 16 GiB. Ratio and throughput are
> size-independent and transfer; the lookup timings are directional only.

Peak RSS for `-d` (decompress) ranges ~31-33 MB across all levels — roughly
2x the raw table size, consistent with holding both the compressed input and
decompressed output resident at once. Task 7 aims to reduce this.
